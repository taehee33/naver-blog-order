# 사진 방향 추천(AI) 자동 테스트

네이버 글쓰기 화면을 흉내 낸 목업(`mock-*.html`)에 확장을 붙여 다음을 확인한다.

1. 설정 창에서 가벼운 모드를 고르면 모델 설치가 끝나 "설치됨"으로 바뀌는지
2. 사진 6장을 올리면 정렬과 AI 분석이 되고, 누운 사진(10·12·28·33)에 회전 추천이 붙는지
3. [네이버 편집기로 N장 돌리기]를 누르면 편집기 썸네일 → 자르기·회전 → 왼쪽 회전 → 적용이 눌리는지
   - 기존 사진과 바로 선 사진(03·30)은 돌리지 않는지
   - [완료]는 누르지 않는지

## 실행 방법

- 테스트용 확장 사본의 `ai-config.js` URL을 `http://localhost:8765/`로 바꾼다.
- `models/`에 `orientation-int8.onnx`를, `imgs/`에 테스트 사진을 넣는다.
- `python3 server.py &`로 모델 서버를 띄운다.
- `EXT=<테스트용 확장 경로> node run.js`로 실행한다.
- 옵션 환경변수
  - `SKIP28=1`: 28번을 제외했을 때 3장만 도는지 확인
  - `AIOFF=1`: AI를 껐을 때 AI 영역이 안 뜨는지 확인

2026-10-22 결과: 세 경우 모두 통과했다. 분석은 6장에 약 7초(모델 로딩 포함)가 걸렸다.

### 실제 네이버 상황 재현 (2026-10-22 추가)

- `MOCK=mock-editor2.html ROUND2=1 node run.js`로 실행한다.
- 이 목업에서는 편집기 썸네일 줄이 접혀 있다가 "이미지 n / m"을 눌러야 나타난다.
- 편집기에는 선택한 사진 주변의 일부만 들어간다.
- 기대 결과
  - 1차: 3장을 돌리고 "남은 1장"이라고 안내한다.
  - 사용자가 [완료]를 누른 뒤 2차: 남은 1장을 돌린다.
- 결과: 통과했다.

### 같은 사진 다시 올리기 (2026-10-22 추가)

- `REUP=1 node run.js`로 실행한다.
- 시나리오: 업로드 → 회전 → [완료] → 사진 전부 삭제 → 같은 사진 다시 업로드 → 다시 인식되어 회전되는지 확인
- 결과: 통과했다. 재인식까지 0.9초가 걸렸다(AI 결과 재사용).

### 적용 후 패널이 닫히는 동작 재현 (2026-10-22 추가)

- 실제 네이버에서는 [적용]을 누르면 자르기·회전 패널은 닫히지만, 자르기 버튼의 `on` 표시는 남는다.
- 목업 두 개(`mock-editor.html`, `mock-editor2.html`)에 이 동작을 반영했다.
- 수정 전: 첫 장만 돌아갔다.
- 수정 후: 기본, 2회차, 다시 올리기, 하나 빼기, ID 불일치 다섯 경우 모두 통과했다.

### 회전이 실제로 됐는지 확인 (2026-10-22 추가)

- 실제 네이버에서 발견한 문제: 패널이 막 열렸거나 사진을 불러오는 중이면 회전 클릭을 무시하는데, 확장은 "돌렸어요"라고 보고했다.
- 목업 반영
  - 사진을 선택하거나 패널을 연 직후 0.7초 동안은 회전 클릭을 무시한다.
  - 회전하면 [재설정](`npe_btn_reset`)의 `disable` 표시가 사라진다.
- 수정 전: "4장 돌렸어요"라고 했지만 실제 회전은 0장이었다. 재현됐다.
- 수정 후: 다섯 시나리오 모두 실제 회전이 확인됐다.
- `MOCK=mock-editor-dead.html` (회전이 전혀 안 먹는 경우): 0장으로 정직하게 안내했다.
